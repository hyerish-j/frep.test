# 프렙 카페 운영 프로그램 제품 요구사항 문서(PRD)

작성일: 2026-10-12  
상태: PRD 기획 완료. 사용자의 ‘모두 추천대로 진행해줘’에 따라 남은 1차 업무 원칙을 추천안으로 채택했다. 계산·화면·기술·상세 동작은 후속 설계 대상으로 남긴다.

## 1. 제품 목표

카페 운영자가 판매 기록을 입력하고, 메뉴별로 얼마나 남는지 확인한 뒤, 같은 기간의 매장 손익과 재료 잔량까지 확인하는 웹 프로그램을 만든다.

PRD는 제품이 해결할 문제, 필요한 기능, 구현 우선순위와 완료 기준을 정리하는 문서다. MVP는 처음부터 모든 기능을 만들지 않고, 가장 중요한 일을 끝까지 할 수 있는 첫 버전이다.

이번 문서는 계산식, 화면 디자인, 기술 선택, 상세 동작, 코드를 정하지 않는다. 자료에서 확인한 사실은 2장에, 사용자 선택과 추천안 일괄 채택에 따른 제품 결정은 3~6장에 구분해 기록한다.

## 2. 자료에서 확인한 사실

검토 자료는 `데이터/데이터설명.md`, `데이터/매장운영데이터.xlsx`, `데이터/매장운영데이터.json`이다. 설명 문서를 읽고 엑셀의 시트·열·기록 수, JSON의 항목·기록 수·기간·대표 기록을 확인했다. 모든 셀의 값이 두 형식에서 완전히 같은지 대조한 검사는 이번 검토에 포함하지 않았다.

### 2.1 자료의 성격과 기간

- 매장명은 프렙 카페이며, 직접 구성한 가상 매장 샘플이다. 실제 매장 거래 실적으로 설명하면 안 된다.
- 판매·재고·비용 기록은 2025-07-01부터 2026-09-18 마감까지 있다.
- 영업달력은 2026-09-30까지 있으나, 9월 19일 이후는 미마감이다. 문서 작성일 현재의 실적으로 오해하면 안 된다.
- 금액은 원이며 부가세를 제외한 금액이다. 재료 수량은 g·ml·개 단위를 사용한다.
- 설명 문서에 따르면 엑셀과 JSON은 같은 기록의 두 형식이다. 두 파일을 별도 실적으로 합산하면 안 된다.
- JSON의 `settings`는 비어 있다. 앞으로의 계산·판단 기준이 합의되어 있다는 뜻이 아니다.

### 2.2 기록 구성

| 기록 | 수 | 확인된 내용과 활용 가능성 |
| --- | ---: | --- |
| 공급사 | 3 | 공급사 식별번호와 이름. 재료의 공급처 확인에 활용 가능 |
| 재료 | 11 | 기준단위, 구매용량, 최초 구매가격, 납기와 안전재고 일수 |
| 메뉴 | 8 | 메뉴명, 판매기준가, 분류, 레시피 버전 |
| 레시피 | 22 | 메뉴 1개당 재료 사용량과 적용 판매채널 |
| 재료가격이력 | 33 | 적용시작일별 구매가격·구매용량. 마지막 적용시작일은 2026-09-01 |
| 영업달력 | 457 | 영업 여부, 마감 여부, 날씨와 메모 |

| 초기재고 | 11 | 2025-07-01 첫 영업 전 재료 수량 |

엑셀에는 위 기록 외에 `데이터안내` 시트가 있다. 이 시트는 설명용이며, 첫 행부터 일반 기록 표가 시작되는 구조가 아니다. JSON은 별도의 `meta` 항목에 출처와 기간 정보를 담고 있다.

비용에는 임차료, 인건비, 관리비, 수도광열비, 광고비, 통신·소프트웨어, 사업주 부담 보험료, 소모품·청소비가 있다.

### 2.3 해석할 때 주의할 점

| 확인된 사실 | 기획에 주는 영향 |
| --- | --- |
| 판매 한 줄은 일자·메뉴·채널별 집계이며 주문 한 건이 아니다 | 기록 수를 주문 수나 고객 수로 설명하지 않는다 |
| 같은 메뉴ID·재료ID·공급사ID는 같은 대상을 가리킨다 | 이름만 보고 서로 다른 기록을 연결하거나 중복 생성하지 않는다 |
| 구매가격은 구매용량 전체의 가격이다 | 한 봉지 가격과 재료 1g·1ml·1개의 가격을 혼동하지 않는다 |
| 레시피에는 모든 채널용 재료와 포장 판매 전용 재료가 있다 | 매장 판매와 포장 판매의 원가·재료 사용을 구분할 필요가 있다 |
| 판매기록에 당시 단가·할인·수수료·개당 식재료 및 포장 원가가 있다 | 자료 자체가 미래 운영 기준을 정하지는 않는다. 채택한 과거 실적 원칙은 4장에 기록한다 |
| 초기재고와 입고·폐기·실사조정이 따로 있다 | 재고 변동 기록만 더한 수량을 재료 잔량으로 오해하지 않는다 |
| 실사조정에는 증감수량과 실제로 센 수량이 함께 있다 | 두 값을 별도 입고처럼 중복 반영하면 안 된다. 채택한 실측 재고 원칙은 6장에 기록한다 |
| 월비용계획과 비용기록은 같은 비용의 월·일 단위 기록이다 | 두 자료를 별도 지출처럼 합산하면 안 된다 |
| 영업 여부와 마감 여부가 구분되어 있다 | 휴무, 미입력, 미마감을 모두 매출 0원으로 취급하지 않는다 |
| 빈칸은 해당 없음 또는 미입력이다 | 빈칸과 실제 0을 구분하고, 필요한 기록이 없으면 그 사실을 알린다 |
| 납기·안전재고 일수는 영업일 기준이다 | 단순한 달력 날짜 수로 바꾸어 발주 기준을 확정하지 않는다 |
| 2025년·2026년은 각각 일부 기간만 실적이 있다 | 연간 조회에서도 기록이 포함된 기간을 알 수 있어야 한다 |

파일에 있는 과거 원가·수수료·비용 배분 결과는 기록의 사실이다. 앞으로 사용할 업무 원칙은 별도의 제품 결정이며, 자료만으로 합의가 있었다고 보지 않는다.

## 3. 사용자와 핵심 흐름

주 사용자는 카페 판매·비용·재고 기록을 관리하는 운영자다. 1차는 한 매장의 한 운영자가 한 기기에서 사용하는 범위다. 공동 사용과 여러 기기 간 기록 공유는 2차로 미룬다.

핵심 흐름은 다음과 같다.

1. 제공된 매장 자료를 바탕으로 판매 기록을 직접 입력하거나 잘못된 기록을 수정·삭제한다.
2. 해당 기록이 반영된 메뉴별 수익성을 확인한다.
3. 같은 기간의 매출·비용·손익을 확인한다.
4. 판매와 재고 기록에 연결된 재료 잔량을 확인하고, 실제로 센 재고와 차이가 있는지 확인한다.
5. 기록을 저장하고, 백업한 기록으로 복원할 수 있다.

예를 들어 아메리카노의 포장 판매 기록을 추가하면 해당 메뉴의 수익성, 매장 손익, 원두와 포장 재료 잔량까지 연결되어야 한다. 사용할 업무 원칙은 이 문서에 기록하고, 정확한 계산식과 반영 절차는 후속 설계에서 정한다.

## 4. 확정된 1차 구현 범위

사용자는 2026-10-12에 A안인 ‘직접 입력부터 결과 확인까지 우선’을 선택했다. 판매·비용 입력·수정·삭제, 메뉴 수익성, 일·월 손익, 입고·폐기·실제 재고 기록과 잔량, 저장·수동 백업·복원을 1차 기능 범위로 확정한다. 엑셀 양식·가져오기, 예상 손익, 부족 재료 판정·발주량 안내, 나머지 기간 단위는 2차로 미룬다.

자료의 메뉴 8개·재료 11개·기존 레시피를 활용하고, 메뉴·레시피·공급사 관리 기능은 2차로 미룬다. 1차 업무 원칙은 사용자의 개별 선택 및 추천안 일괄 채택에 따라 아래와 6장에 기록한다.

| 기능 | 1차에 필요한 결과 | 범위 제한 |
| --- | --- | --- |
| 시작 자료 활용 | 제공된 과거 기록으로 핵심 흐름을 확인할 수 있다 | 동일 자료를 한 번만 반영한다. 사용자가 임의 파일을 가져오는 기능은 2차 |
| 판매 기록 관리 | 판매 기록을 직접 입력·수정·삭제하고 결과에서 확인한다 | 기존 메뉴와 판매채널을 대상으로 한다. 주문별 관리·환불 전용 처리는 2차 |
| 메뉴별 수익성 확인 | 선택한 기간에 메뉴별로 얼마나 남는지 비교할 수 있다 | 할인과 식재료·포장·결제수수료를 고려한다. 임차료·인건비 등은 메뉴별로 나누지 않는다. 자동 등급·추천은 2차 |
| 비용 기록 관리 | 비용을 직접 입력·수정·삭제하고 손익에서 확인한다 | 날짜별 비용 기록을 사용한다. 월비용을 자동으로 나누는 편의 기능은 2차 |
| 기간별 실적과 손익 | 매출·비용·손익과 기록이 포함된 기간을 확인한다 | 일·월 조회부터 제공하고 자료의 운영비 8개 항목을 모두 포함한다. 미래 예상 손익은 2차 |
| 재고 기록과 잔량 | 입고·폐기·실제로 센 재고를 기록하고 재료별 잔량을 확인한다 | 기존 재료만 대상으로 한다. 실제로 센 수량을 이후 잔량의 기준으로 삼는다 |
| 저장·백업·복원 | 다시 이용할 때 기록을 이어가고, 백업으로 기록을 복구한다 | 한 기기에서 이어 쓰고 수동으로 전체 기록을 백업·복원한다. 여러 백업의 합치기는 2차 |

부족한 재료를 판정하는 기준과 필요한 발주량 안내는 2차로 미룬다. 1차에서는 재료 잔량을 확인해 운영자가 보충 필요성을 판단하는 데 집중한다.

### 확정된 메뉴 수익성의 의미

사용자는 메뉴 수익성 질문에서도 A안인 ‘판매에 직접 드는 비용까지’를 선택했다. 메뉴 수익성은 할인과 식재료·포장·결제수수료를 고려한 뒤 남는 금액을 의미한다. 임차료·인건비 등 매장 운영비는 메뉴별로 나누지 않고 매장 전체 손익에서 확인한다. 따라서 메뉴에서 남는 금액을 매장의 최종 이익으로 설명하지 않는다.

과거 판매는 판매 당시 기록을 유지한다. 새 판매는 판매 날짜에 적용되는 재료 가격이력을 활용하고 결제수수료는 실제 금액을 기록한다. 수정할 때도 관계없는 과거 판매를 현재 가격으로 바꾸지 않는다. 계산식과 수정 항목별 상세 처리는 후속 설계에서 정한다.

### 확정된 매장 손익의 운영비 범위

사용자는 운영비 항목 질문에서 A안인 ‘자료에 있는 운영비 8개 항목을 모두 포함’을 선택했다. 매장 전체 손익에는 임차료, 인건비, 관리비, 수도광열비, 광고비, 통신·소프트웨어, 사업주 부담 보험료, 소모품·청소비를 모두 포함한다.

메뉴 수익성에 반영한 직접 비용이나 같은 비용의 월·일 기록을 중복으로 반영하지 않는다. 세금 등 자료에 없는 비용까지 포함한 최종 이익으로 설명하지 않는다. 1차는 날짜별 비용기록의 날짜를 기준으로 확인하며 월비용계획을 별도 지출로 합산하지 않는다. 새 비용도 적용할 날짜와 항목·금액을 직접 기록한다. 따라서 날짜별 손익은 비용을 기록한 날짜에 따라 달라질 수 있다.

1차 손익은 판매에 연결된 직접 비용과 운영비 8개 항목을 다룬다. 입고 구매대금을 판매 재료 원가와 별도 비용으로 중복 반영하지 않는다. 폐기는 1차에서 재고 수량에 반영하고, 폐기 손실금액의 별도 손익 반영은 2차로 미룬다. 이 제한을 손익의 의미와 함께 설명한다.

### 확정된 과거 판매의 기준

사용자는 가격 변경 시 과거 실적 질문에서 A안인 ‘판매 당시 기록을 유지’를 선택했다. 과거 판매의 수익성은 당시 기록된 원가·수수료·판매단가를 기준으로 확인하며, 이후 재료 가격이 바뀌었다는 이유만으로 과거 실적을 바꾸지 않는다. 예를 들어 9월에 원두 가격이 올라도 8월 판매 실적은 바뀌지 않는다.

현재 재료 가격을 적용한 별도 비교는 1차에 포함하지 않는다. 잘못 입력한 기록은 바로잡을 수 있지만 가격 변경만으로 다른 과거 기록의 금액을 일괄 변경하지 않는다.

| 기획 | 25분 | 1차 범위와 핵심 운영 기준 합의 |
| 화면 설계 | 20분 | 핵심 흐름을 사용할 수 있는 구성 정리 |
| 개발 | 135분 | 입력·수정·삭제부터 결과 확인, 저장·백업·복원까지 연결 |
| 검사 | 40분 | 아래 완료 기준과 자료 해석 오류 확인 |
| 배포 | 20분 | 합의한 환경에서 프로그램을 열고 핵심 흐름 확인 |
| 합계 | 240분 | 기획·설계·개발·검사·배포 포함 |

이는 제한된 첫 버전에 대한 작업 예산이며 완료 보장은 아니다. 한 운영자의 한 기기 사용과 제공 자료 활용을 전제로 한다. 배포는 그 기기에서 웹 프로그램을 열어 핵심 흐름을 사용할 수 있는 수준으로 한정하고, 계정·공동 사용·외부 서비스 연동은 포함하지 않는다. 실행 환경과 배포 방식은 후속 기술 설계에서 확인한다. 시간이 부족할 때 핵심 흐름의 연결과 저장·복구 검사를 생략하지 않는다. 범위 변경은 사용자가 선택한다.

### 4.2 1차 완료 기준

- 제공된 판매·비용·재고 기록으로 메뉴 수익성, 기간 손익, 재료 잔량을 확인할 수 있다.
- 판매 기록을 입력·수정·삭제한 결과가 메뉴 수익성, 기간 실적·손익, 관련 재료 잔량에 함께 반영된다.
- 비용을 입력·수정·삭제한 결과가 해당 기간 손익에 반영된다.
- 입고·폐기·실제 재고 기록이 합의한 기준에 따라 잔량에 반영된다.
- 일·월 조회 결과에서 실제 기록 범위와 미마감 여부를 구분할 수 있다.
- 이후 재료 가격이 바뀌어도 과거 판매의 수익성이 가격 변경만으로 달라지지 않는다.
- 새 판매는 판매 날짜에 적용되는 가격이력을 기준으로 확인한다. 필요한 가격이나 수수료가 없으면 0으로 가정하지 않고 확인이 필요함을 알린다.
- 실측 재고 이후의 잔량과 실측 전 기록을 구분하고, 실사조정에 의해 재고가 두 번 바뀌지 않는다.
- 과거 원가, 포장 전용 재료, 비용 중복, 초기재고, 실사조정, 빈칸에 관한 합의 기준을 지킨다.
- 저장한 기록을 다시 확인할 수 있고, 백업으로 복원한 뒤 기록과 핵심 결과가 일치한다.
- 합의한 배포 환경에서 운영자가 판매 입력부터 재료 잔량 확인까지 끝낼 수 있다.

정확한 값에 대한 검사 기준은 이 문서의 업무 원칙을 바탕으로 후속 계산 설계에서 마련한다. 이 문서에서는 숫자나 계산식을 임의로 정하지 않는다.

## 6. 추천안 일괄 채택으로 정한 업무 원칙

사용자는 2026-10-12에 ‘모두 추천대로 진행해줘’라고 요청했다. 아래 내용은 자료에서 발견한 사실이 아니라, 그 요청에 따라 담당자가 선택한 1차 추천안이다. 새 기능을 늘리지 않고 핵심 흐름과 4시간 범위에 맞춰 정했다.

| 주제 | 채택한 원칙 | 쉬운 예시와 추천 이유 |
| --- | --- | --- |
| 새 판매의 재료 가격 | 판매 날짜에 적용되는 재료 가격이력을 활용한다 | 8월 판매를 나중에 입력해도 8월에 적용되던 가격을 쓴다. 매번 원가를 직접 입력하는 부담을 줄인다 |
| 가격 정보 부족 | 필요한 가격이 없거나 유효성을 확인할 수 없으면 확인 필요로 알리고, 원가를 0으로 가정하지 않는다 | 샘플의 마지막 가격이 오늘도 맞는지는 자료만으로 알 수 없다. 현재 실제 가격을 만들어 넣지 않는다 |
| 새 판매의 결제수수료 | 실제 수수료 금액을 직접 기록한다. 수수료율은 자동 추정하지 않는다 | 면제된 경우 실제 0을 적고, 모르는 경우 0으로 채우지 않는다. 자료에 없는 결제 조건을 가정하지 않는다 |
| 판매 기록 수정 | 잘못 입력한 대상 기록을 바로잡고 그 기록에 연결된 결과를 갱신한다. 다른 과거 판매는 당시 기록을 유지한다 | 어제 판매수량을 고쳐도 지난달의 원가가 현재 가격으로 바뀌지 않는다. 항목별 원가 재확인 절차는 후속 설계 사항이다 |
| 재료 사용 | 기존 레시피와 판매채널에 맞는 재료 사용을 잔량에 반영한다 | 포장 판매에는 해당 포장 재료도 반영한다. 매장 판매에 포장 전용 재료를 적용하지 않는다 |
| 실제 재고 | 실제로 센 수량을 해당 시점 이후 잔량의 기준으로 삼고, 그때의 장부와 차이를 구분해 기록한다 | 장부에 원두 1,000g, 실측에 900g이면 이후 잔량은 실측을 기준으로 본다. 차이를 입고처럼 다시 더하지 않는다 |
| 실측 이전 기록의 수정 | 과거 기록과 그 시점의 차이를 바로잡되, 이미 실제로 센 수량 자체는 판매 기록 수정만으로 바꾸지 않는다 | 실측 이전 판매수량 오류를 고쳐도 실제로 900g을 센 사실은 유지한다. 중복 조정을 방지한다 |
| 비용 기록 | 기존 날짜별 비용기록을 사용한다. 월비용계획은 별도 지출로 합산하지 않는다. 새 비용은 날짜별로 직접 기록한다 | 날짜별 월세 기록과 월비용계획의 월세를 두 번 반영하지 않는다. 자동 기간 배분은 2차로 미룬다 |
| 미마감과 기록 범위 | 미마감 기록은 확정 실적과 구분하고, 기록이 없는 날짜를 임의로 판매 0으로 보지 않는다 | 9월 조회에서 18일까지의 실적을 9월 전체 실적처럼 설명하지 않는다. 마감 상태 변경의 상세 절차는 후속 설계에서 정한다 |
| 사용과 저장 | 한 매장의 한 운영자가 한 기기에서 기록을 이어 쓴다 | 개인 운영 장부부터 완성해 공동 사용과 동시 수정 부담을 줄인다. 저장 기술은 선택하지 않는다 |
| 백업과 복원 | 기준 자료와 운영 기록을 포함한 전체 자료를 수동 백업하고, 선택한 백업 시점의 전체 자료로 되돌린다. 여러 자료를 합치는 복원은 2차로 미룬다 | 어제 백업으로 복원하면 장부와 결과도 어제 상태로 돌아온다. 복원 전 현재 기록 보호와 파일 확인 절차는 후속 설계에서 정한다 |
| 배포 범위 | 운영자의 한 기기에서 웹 프로그램을 열고 핵심 흐름을 사용할 수 있는 수준으로 한정한다 | 공개 서비스, 계정, 외부 서비스 연동 없이 첫 버전을 확인한다. 구체적인 배포 기술과 주소는 후속 설계 사항이다 |

위 원칙에서 실제 가격·수수료 금액 같은 운영 입력값은 자료에 없으면 별도로 확인해야 한다. 이는 미정 요구사항을 임의 확정한 것이 아니라, 프로그램이 모르는 값을 추정하지 않도록 정한 업무 원칙이다.

## 7. 후속 설계와 2차 기획에 남기는 내용

### 7.1 1차 후속 설계 사항

- 계산식, 금액의 반올림, 수익률 표시 방법, 입력 검증.
- 같은 날짜·메뉴·채널 기록의 중복 처리, 판매 수정·삭제의 확인 절차.
- 미마감 판매의 표시·집계와 마감 상태 관리 절차.
- 날짜 단위 자료에서 입고·판매·폐기·실측의 처리 순서와 실측 기준 시점.
- 백업 파일 형식, 손상·호환성 검사, 복원 전 기존 기록 보호 절차.
- 화면 구성, 버튼·입력칸, 저장 기술, 실행 환경, 배포 방식.

이 항목들은 이번 PRD에서 정하지 않도록 요청받은 상세 설계 사항이다. 이후 사용자 요청에 따라 `docs/02_FRD.md`를 작성했고, 2026-10-12 ‘모두 추천으로 진행해줘’에 따라 1차 기능의 계산·처리·예외 기준을 해당 문서에서 확정했다. 계산식과 상세 동작은 PRD에 복사하지 않는다. 화면의 정확한 배치·저장 기술·실행 환경·배포 방식은 후속 구현 설계에서 정한다.

### 7.2 2차 기획 사항

주·분기·반기·연간 기간 기준, 예상 손익의 기간과 가정, 부족 재료 판정과 발주량 기준, 엑셀 양식·가져오기 및 중복 처리, 자동 등급·개선 제안, 폐기 손실금액 기준은 2차 구현 전에 정한다. 자료에 있는 납기와 안전재고 일수만으로 위 정책이 이미 확정된 것으로 보지 않는다.
