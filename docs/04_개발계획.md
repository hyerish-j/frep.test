# 프렙 카페 운영 프로그램 1차 개발 계획

작성일: 2026-10-12  
상태: 개발 계획 사용자 확인 완료. EPIC 1은 구현·자동 검사 41개 및 사용자 화면 확인 U01~U10을 통과하여 2026-10-12 완료했다. EPIC 2·3은 미착수이며 GitHub 등록·Vercel 배포는 아직 수행하지 않았다.

## 1. 전체 작업 순서와 나눈 이유

**1차 개발은 EPIC 3개, User Story 14개**로 구성한다. EPIC은 함께 완성할 작업 묶음이고, Story는 사용자가 한 가지 목적을 달성하는 기능이다.

| 순서 | EPIC | Story 수 | 끝났을 때 확인할 결과 |
| --- | --- | ---: | --- |
| 1 | 판매 기록으로 메뉴 수익성과 재료 잔량 확인 | 5 | 판매 입력·수정·삭제가 수익성과 잔량에 반영되고, 다시 접속해도 유지됨 |
| 2 | 운영비를 반영해 매장 손익 확인 | 4 | 비용 입력·수정·삭제가 일·월 매장 손익에 반영됨 |
| 3 | 실제 재고 기록과 백업·복원 | 5 | 입고·폐기·실측을 반영하고, 전체 자료를 백업·복원할 수 있음 |
| **합계** | **3개** | **14개** | 판매부터 손익·재고·복구까지 연결 |

판매 기록과 계산을 먼저 완성하고, 그 결과에 운영비를 연결한다. 이후 재고 변동 입력과 전체 자료 복구를 완성한다. 각 EPIC을 실제 화면에서 확인할 수 있도록 나눈다.

최초 자료 반영, 저장소 구성, 공통 입력 검사, 기간 선택 등은 관련 Story에 필요한 개발 작업으로 포함한다. 별도의 기술 작업을 사용자 Story로 세지 않으며, 계산·저장·오류 검사는 각 Story에서 함께 수행한다.

기준 문서는 `docs/01_PRD.md`, `docs/02_FRD.md`, `docs/03_TRD.md`다. 기능·사용 순서·계산 기준을 바꾸지 않는다. `design/_1`, `_2`, `_3` 및 `design/artisan_operational_ledger/DESIGN.md`는 시각적 참고 자료로 활용하며 시안의 고정 숫자와 예시 동작을 실제 처리 기준으로 사용하지 않는다.

## 2. EPIC 1. 판매 기록으로 메뉴 수익성과 재료 잔량 확인

**포함 Story: 1-1~1-5, 총 5개.**

제공 자료 반영과 지속 저장을 먼저 준비하고, 판매 입력 → 수익성·잔량 조회 → 수정·삭제 순으로 구현한다. 판매 시안 `_1`, 수익성 시안 `_2`, 재고 시안 `_3`의 조회 부분을 활용한다.

| Story | 사용자가 할 수 있는 일 | 자동 검사 | 사용자가 화면에서 확인할 행동과 예상 결과 |
| --- | --- | --- | --- |
| **1-1. 판매 기록 등록** — F01·F03·F13 | 기존 기록을 확인하고 날짜·메뉴·채널·수량·단가·할인·수수료를 입력해 판매를 등록한다. | 샘플 최초 1회 반영, 날짜별 원가·레시피 적용, 순매출 계산, 빈칸/0 구분, 중복·미래 날짜·과다 할인 차단, 저장 실패 시 이전 자료 유지를 검사한다. | 없는 날짜·메뉴·채널 조합으로 판매를 등록한다. 목록에 한 건이 추가되고 새로고침 후에도 남는다. 같은 조합을 다시 등록하면 기존 수정 안내가 나온다. |
| **1-2. 메뉴 수익성 확인** — F02·F06 | 일·월과 채널을 선택해 메뉴별 매출·직접 비용·남는 금액을 확인한다. | 당시 원가 유지, 포장 전용 비용, 실제 수수료, 전체 매출 기준 마진율, 반올림, 원가 누락·매출 0 처리를 검사한다. | 등록한 판매가 포함된 기간을 선택한다. 해당 메뉴의 수량·매출·수익이 반영된다. 채널을 바꾸면 대상 기록만 집계되고, 임차료 같은 운영비는 메뉴 원가에 섞이지 않는다. |
| **1-3. 재료 잔량 확인** — F02·F10 | 재료를 검색하고 선택한 날짜까지의 잔량과 최근 실측 정보를 확인한다. | 초기재고·판매 사용량·기존 입고/폐기·종료 실측의 계산, 포장 조건, 실사조정 중복 방지, 누락·음수 잔량 처리를 검사한다. | 판매 전후 같은 종료일 잔량을 비교한다. 판매에 사용된 재료가 줄고 포장 판매에서는 포장 재료도 줄어든다. 가격 정보만 부족한 경우에도 사용량이 유효하면 잔량은 확인된다. |
| **1-4. 판매 오류 수정** — F04 | 잘못 입력한 판매 한 건을 바로잡는다. | 수량·금액 수정 시 기존 개당 원가 유지, 날짜·메뉴·채널 변경 시 원가 재확인, 중복 차단, 변경 전후 기간 갱신, 실측량 보존, 실패 시 원본 유지를 검사한다. | 판매수량을 수정한다. 목록·수익성·관련 잔량이 바뀐다. 날짜나 채널을 바꾸면 원가 변경 확인이 나오며, 관계없는 과거 판매는 유지된다. |
| **1-5. 잘못 등록한 판매 삭제** — F05 | 불필요한 판매 한 건을 확인 후 삭제한다. | 취소 시 유지, 대상 한 건만 삭제, 매출·직접 비용·재료 사용량 제거, 실측 사실 유지, 삭제 실패 시 원본 유지를 검사한다. | 삭제를 취소하면 변화가 없다. 다시 삭제를 확정하면 기록과 연결된 수익·사용량이 제거되고, 새로고침 후에도 삭제 상태가 유지된다. |

### 완료 기준

- 실제 자료와 저장된 입력값으로 판매·수익성·재고 화면이 작동한다.
- 일·월 조회, 필터, 20행 페이지와 전체 조회 범위 합계가 맞는다.
- 미마감·변경 날짜는 잠정으로 표시하고, 기록 없음·실제 0·계산 불가를 구분한다.
- 판매 입력·수정·삭제 후 재접속해도 기록과 계산 결과가 유지된다.
- 기존 실측 이전 판매를 수정해도 실제로 센 수량은 바뀌지 않는다.

## 3. EPIC 2. 운영비를 반영해 매장 손익 확인

**포함 Story: 2-1~2-4, 총 4개.**

EPIC 1의 판매·직접 비용 계산과 저장 기능을 사용한다. 시안에 빠진 매장 손익 화면과 비용 관리 화면을 보완한다. 구현은 기존 자료의 손익 조회부터 시작하고 비용 입력·수정·삭제를 연결한다.

| Story | 사용자가 할 수 있는 일 | 자동 검사 | 사용자가 화면에서 확인할 행동과 예상 결과 |
| --- | --- | --- | --- |
| **2-1. 운영비 등록** — F07 | 날짜·운영비 항목·금액을 입력해 비용을 등록한다. | 운영비 8개 항목, 정수 금액·0/빈칸, 미래 날짜 차단, 유사 중복 확인, 저장 실패·재접속 유지를 검사한다. | 소모품·청소비 1,000원을 등록한다. 비용 목록에 남고 해당 기간 운영비에 반영된다. 같은 날짜·항목을 다시 입력하면 확인 안내가 나온다. |
| **2-2. 비용 오류 수정** — F08 | 잘못된 비용의 날짜·항목·금액을 바로잡는다. | 변경 전후 기간 재집계, 메뉴 직접수익·재료 수량 불변, 잠정 상태, 실패 시 원본 유지를 검사한다. | 1,000원을 1,500원으로 수정한다. 해당 기간 운영비가 500원 늘고 손익이 500원 줄어든다. 메뉴 수익성과 재료 수량은 그대로다. |
| **2-3. 잘못 등록한 비용 삭제** — F08 | 불필요한 비용 한 건을 확인 후 삭제한다. | 취소·단일 삭제·손익 재집계·실패 시 유지·재접속을 검사한다. | 삭제를 취소하면 변화가 없다. 확정하면 해당 비용만 사라지고 손익이 그 비용만큼 증가한다. |
| **2-4. 일·월 매장 손익 확인** — F02·F09 | 전체 메뉴·채널의 매출과 운영비를 함께 보고 매장 손익을 확인한다. | 전체 직접수익−운영비 계산, 8개 항목 포함, 월비용계획·입고대금 중복 제외, 누락·부분 기간·잠정 상태를 검사한다. | 같은 기간의 메뉴 직접수익 전체 합계와 매장 손익을 비교한다. 차이는 운영비 합계와 일치한다. 메뉴 화면의 채널 필터를 바꿔도 매장 손익은 전체 채널 기준을 유지한다. |

### 완료 기준

- 판매 → 메뉴 수익성 → 같은 기간 매장 손익 → 재료 잔량의 핵심 흐름이 연결된다.
- 비용 입력·수정·삭제가 실제 저장되며 해당 기간 손익에 반영된다.
- 월비용계획, 재료 구매대금, 폐기 손실금액을 별도 비용으로 중복 반영하지 않는다.
- 없는 비용·미마감 날짜를 임의로 채워 확정 손익처럼 표시하지 않는다.

## 4. EPIC 3. 실제 재고 기록과 백업·복원

**포함 Story: 3-1~3-5, 총 5개.**

앞선 EPIC의 재고 계산과 전체 저장 구조를 사용한다. 입고 → 폐기 → 실측 → 백업 → 복원 순으로 구현한다. 재고 입력은 시안 `_3`을 활용하고 백업·복원 확인 절차를 보완한다.

| Story | 사용자가 할 수 있는 일 | 자동 검사 | 사용자가 화면에서 확인할 행동과 예상 결과 |
| --- | --- | --- | --- |
| **3-1. 재료 입고 등록** — F11 | 날짜·재료·기준단위 수량을 입력해 입고를 기록한다. | 양수 수량, g/ml 소수·개 정수, 단위·날짜, 저장 실패, 실측 전후 적용을 검사한다. | 최근 실측 이후 원두 500g을 입고한다. 해당 날짜 이후 잔량이 500g 증가하고 새로고침 후에도 유지된다. |
| **3-2. 재료 폐기 등록** — F11 | 폐기한 재료의 날짜·수량·사유를 기록한다. | 양수 입력을 음수 변동으로 변환, 사유 필수, 과다 폐기 확인, 음수 잔량 표시, 실패 시 유지를 검사한다. | 최근 실측 이후 원두 200g을 폐기한다. 잔량이 200g 줄어든다. 사유가 없으면 저장되지 않고, 잔량보다 많으면 경고와 추가 확인이 나온다. |
| **3-3. 실제로 센 재고 등록** — F12 | 하루 종료에 실제 센 수량을 기록하고 장부와의 차이를 확인한다. | 같은 재료·날짜 중복 차단, 실측 0 허용, 차이 사유, 당일 처리 순서, 실측 이전 기록 수정 시 실측량 보존을 검사한다. | 장부 1,000g인 재료를 실측 900g으로 기록한다. 차이 −100g과 잔량 900g이 표시된다. 이전 판매를 수정하면 차이는 재계산되지만 실측 900g은 유지된다. |
| **3-4. 전체 자료 백업** — F14 | 현재 운영 자료 전체를 JSON 파일로 내려받는다. | 모든 기준·운영 기록·당시 원가·잠정 상태 포함, 일관된 한 시점의 자료 추출, 필터/페이지에 따른 누락 방지, 파일 생성 실패를 검사한다. | 특정 메뉴만 조회한 상태에서 백업한다. 생성 파일에는 다른 메뉴와 비용·재고도 포함된다. 프로그램은 다운로드 요청을 알리며 실제 파일 저장 완료를 단정하지 않는다. |
| **3-5. 백업 시점으로 복원** — F15 | 백업을 검사하고 현재 자료를 보호한 뒤 전체 자료를 되돌린다. | 형식·버전·매장·자료 구분·ID·단위·연결·중복 검사, 보호 파일 확인, 취소, 전체 대체 실패 시 유지, 복원 전후 결과 일치를 검사한다. | 백업 후 판매·비용·재고를 변경하고 복원한다. 보호 파일을 저장·확인한 뒤 진행하면 기록과 결과가 백업 시점으로 돌아온다. 잘못된 파일이나 취소는 현재 자료를 바꾸지 않는다. |

### 완료 기준

- 입고·폐기·실측이 잔량에 정확히 반영되고 실제 저장된다.
- 원래 실측량과 조정 기록을 보존하며 재고를 두 번 조정하지 않는다.
- 백업 → 자료 변경 → 복원 후 기록·과거 원가·잠정 상태·핵심 계산 결과가 일치한다.
- 복원 도중 실패해도 일부 자료만 바뀌지 않는다.
- GitHub 코드 보관과 Vercel 운영 주소에서 전체 핵심 흐름을 확인한다.

## 5. 모든 Story에 적용할 완료 원칙

자동 검사는 미리 정한 예상값과 실제 계산·저장 결과를 비교하는 검사다. 화면 확인은 정상 사용뿐 아니라 잘못된 입력·취소·재접속도 포함한다.

- 계산은 FRD C01~C06을 그대로 사용한다. 소수 유지, 최종 반올림, 마진율의 백분율 표시까지 검사한다.
- 저장 성공은 실제 저장이 끝난 뒤 표시한다. 실패하면 이전 자료와 입력 내용을 유지한다.
- 빈칸을 0으로 채우거나, 빠진 비용을 제외한 부분 합계를 완전한 이익처럼 보여주지 않는다.
- EPIC 2에서 판매 변경→매장 손익 연결을, EPIC 3에서 모든 변경→백업·복원 연결을 다시 검사한다.
- 고정 수치·가짜 완료 메시지·작동하지 않는 버튼으로 완료 처리하지 않는다.

각 Story의 자동 검사는 TRD에 정한 계산·저장 검사와 실제 브라우저 검사로 구현한다. 통과 여부를 기록하고 실패를 수정한 뒤 해당 Story를 완료 처리한다. 화면 확인은 정상 저장이 이루어지는 시험 환경에서 수행한다.

## 6. 시간 예산과 1차 범위

기획 25분·화면 설계 20분·개발 135분·검사 40분·배포 20분의 **총 4시간 예산**을 유지한다. 각 Story의 검사 준비는 개발과 함께 진행하고, 검사 40분에는 연결·오류·복원 확인을 집중한다. 시간 부족 시 필수 검사나 기능을 조용히 생략하지 않고 남은 작업을 알린다.

엑셀 양식·가져오기, 주·분기·반기·연간 조회, 예상 손익, 부족 재료 판정·발주량, 메뉴·레시피·가격 관리, 재고 기록 수정·삭제, 자동 백업·여러 기기·공동 사용 등 PRD의 2차 기능은 이번 EPIC에 포함하지 않는다. 개발 과정에서 새 기능이나 계산 기준을 임의로 추가하지 않는다.
