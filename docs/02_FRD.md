# 프렙 카페 운영 프로그램 기능 요구사항 문서(FRD)

작성일: 2026-10-12  
상태: 1차 기능 요구사항 확정. 사용자의 추천안 일괄 채택에 따라 입력·처리·결과·오류·계산 기준을 정리했다. 구현·검사는 후속 작업이다.

## 1. 문서의 목적과 읽는 방법

FRD는 사용자가 무엇을 입력하거나 누르면 프로그램이 무엇을 처리하고, 어떤 결과를 보여주고 저장하는지 설명하는 문서다. 이 문서만으로 1차 기능과 처리 흐름, 계산 기준, 오류와 예외를 확인할 수 있도록 작성했다.

검토 자료:

- `docs/01_PRD.md`: 사용자의 개별 A안 선택과 ‘모두 추천대로 진행해줘’를 반영한 PRD.
- `design/_1/code.html`, `design/_1/screen.png`: 판매 기록 관리 및 신규 판매 입력창.
- `design/_2/code.html`, `design/_2/screen.png`: 메뉴 수익성.
- `design/_3/code.html`, `design/_3/screen.png`: 재고 관리 및 입고·폐기·실사 입력창.
- `design/artisan_operational_ledger/DESIGN.md`: 색상·글꼴·표·버튼 등 표현 지침. 기능 승인 근거로 사용하지 않는다.
- `데이터/데이터설명.md`, `데이터/매장운영데이터.json`: 기록의 의미와 실제 메뉴·재료·레시피 확인.

문서의 상태 표시는 다음과 같다.

| 표시 | 의미 |
| --- | --- |
| 확정 | PRD 및 사용자 선택·추천안 일괄 채택에 따라 정한 기능과 처리 기준 |
| 시안 확인 | 실제 HTML·이미지에 있는 요소. 구현 승인이나 데이터 정확성을 뜻하지 않음 |
| 후속 설계 | 기능을 바꾸지 않는 화면 배치·저장 기술·파일 내부 구조 등 구현 설계 |
| 운영 확인 | 실제 가격·수수료·누락 자료처럼 운영자가 확인해야 하는 사실 |
| 2차 | PRD에서 첫 버전 이후로 미룬 기능. 현재 구현하지 않음 |

2026-10-12 사용자의 ‘모두 추천으로 진행해줘’에 따라 F01~F15의 상세 처리와 C01~C06의 계산 기준을 추천안으로 채택했다. 이전에 미정이던 관련 예외도 8장에 정리한 범위 안에서 결정했다. 이 결정은 자료에서 확인한 사실과 구분하며, 시안의 추가 기능이나 2차 기능을 1차에 포함하는 승인은 아니다.

### 2.2 기본 자료와 용어

- 제공 자료는 가상 샘플이다. 판매·재고·비용은 2025-07-01~2026-09-18 마감까지, 영업달력은 2026-09-30까지 있다. 현재 날짜의 실제 매장 자료로 표시하지 않는다.
- 판매 한 줄은 날짜·메뉴·판매채널별 판매 집계다. 주문 한 건이 아니다. ‘판매수량’과 ‘기록 수’를 별도로 표시하며 고객 수는 산출하지 않는다.
- 메뉴 8개: 아메리카노, 카페라떼, 바닐라라떼, 초콜릿라떼, 말차라떼, 레몬에이드, 크루아상, 치즈케이크.
- 재료 11개는 자료의 I01~I11을 사용한다. I10은 포장컵세트, I11은 디저트포장세트다. 공급사·레시피·가격이력은 기존 자료를 사용하며 편집 기능은 2차다.
- 판매채널은 매장·포장이다. 시안의 ‘매장 홀’·‘포장 테이크아웃’은 같은 채널을 나타내는 표시 이름이다. 저장 기준은 매장·포장으로 통일한다.
- 금액은 원·부가세 제외다. 이미 부가세 제외인 금액에서 부가세를 다시 빼지 않는다. g·ml·개는 서로 합산하지 않는다.
- ‘순매출’은 할인 반영 후 판매금액, ‘메뉴 직접수익’은 식재료·포장·수수료까지 고려한 금액, ‘매장 손익’은 여기에 운영비까지 고려한 금액이다.
- ‘당시 원가’는 그 판매에 남겨둔 개당 원가다. 나중에 재료 가격이 바뀌어도 기존 기록을 현재 가격으로 바꾸지 않는다.
- ‘장부 잔량’은 기록으로 산출한 재고, ‘실측 수량’은 사람이 실제로 센 수량, ‘실사조정’은 두 수량의 차이를 반영하는 기록이다.
- 월비용계획과 날짜별 비용기록은 같은 비용의 다른 표현이다. 1차는 날짜별 비용기록을 사용한다.

## 3. PRD와 시안 대조 및 반영 기준

2026-10-12 사용자 답변 ‘추천대로 진행해줘’에 따라 Q01의 A안을 채택했다. 1차는 PRD의 필수 기능을 모두 포함하고, 시안의 추가 요소는 아래처럼 제외하거나 기존 2차 범위로 유지한다. 실제 메뉴·재료를 자료에 맞추고 빠진 비용 관리·매장 손익·복원 화면을 보완해야 한다. 이후 ‘모두 추천으로 진행해줘’에 따라 Q02~Q08과 관련 처리 기준도 채택했다. 이번 작업은 FRD 작성이며 시안 수정과 프로그램 구현은 후속 작업이다.

HTML에는 입력창 열기·닫기, 체크박스 선택, 재고 검색, 카드 전환 등의 시연 동작이 있다. 판매 등록은 창을 닫을 뿐이며, 재고 등록은 알림 후 창을 닫는다. 지속 저장이나 실제 집계 갱신은 확인되지 않았다. 수익성 채널 버튼은 색상만 바꾼다. 이는 완성된 운영 기능의 증거가 아니다.

## 4. 공통 처리 원칙과 화면 동작

### 4.1 조회 범위

사용자는 일 또는 월을 선택한다. 판매·메뉴 수익성·손익 결과는 같은 선택 기간을 기준으로 보여준다. 시안의 판매 메뉴·채널 필터, 수익성 채널 필터, 재고 이름·번호 검색은 기본 목록 조회의 동작으로 유지한다. 안전재고 상태 필터와 3장의 제외 요소는 제공하지 않는다.

- 날짜 범위는 시작일과 종료일 모두 포함한다. 월은 달력상의 1일부터 말일까지다. 1차는 일·월만 조회하며 시안의 임의 기간 입력은 일 또는 월 선택으로 맞춘다.
- 시작 조회일은 저장된 판매·비용·재고 중 마지막 기록일이다. 새 입력 날짜는 한국 기준 오늘을 기본값으로 하며 날짜를 바꿀 수 있다. 과거 판매를 고칠 때는 원래 날짜를 유지한다. 2026-10-12를 자동으로 샘플 실적일로 표시하지 않는다.
- 선택한 월, 실제 기록이 포함된 기간, 미마감 날짜 유무를 각각 알린다. 저장된 미마감 판매도 집계하며 결과에 ‘잠정’을 표시한다. 세부 마감 상태 기준은 8장을 따른다.
- 목록의 페이지를 바꾸더라도 상단 합계는 페이지의 몇 줄이 아니라 선택 범위 전체를 기준으로 한다.
- 판매 채널 필터를 매장 손익에 그대로 적용해 전체 운영비를 특정 채널 비용으로 오해하게 하지 않는다. 매장 손익은 전체 채널을 기준으로 한다.
- 재고는 선택한 날짜 종료 시점의 기록상 잔량이다. 아직 그날이 끝나지 않았으면 현재까지 입력한 기록 기준의 잠정 잔량으로 설명한다. 월 조회는 그 월 조회 종료 시점의 잔량이며 날짜별 잔량을 더하지 않는다.
- 유효한 기록이 없는 상태와 실제로 판매 0인 상태를 구분한다. 필터 결과 없음은 ‘검색 결과 없음’, 기록 범위 밖은 ‘기록 없음’으로 알린다.

### 4.2 입력·저장·연결 결과

사용자가 등록·수정·삭제를 완료하면 대상 기록을 저장하고 그 기록과 연결된 판매 합계·메뉴 수익성·손익·재고를 갱신한다. 저장 성공 전에는 성공 메시지나 확정 집계를 표시하지 않는다. 취소·닫기는 자료를 변경하지 않는다.

정상 입력과 저장 실패를 구분하고, 실패한 입력값은 다시 고칠 수 있도록 유지한다. 여러 번 저장 버튼을 누른 같은 요청이 중복 기록되지 않도록 한다. 아직 저장하지 않은 내용을 가지고 이동·닫기·취소할 때는 버릴지 계속 입력할지 확인한다. 입력하지 않았으면 바로 닫는다.

### 4.3 파일 결과

기록 등록·수정·삭제는 작업 중인 저장 자료에 반영하며 매번 내려받을 파일을 만들지는 않는다. 조회·필터·취소는 운영 기록을 변경하지 않는다. 내려받는 필수 파일은 전체 백업이며, 복원은 그 파일의 전체 자료로 작업 자료를 되돌리는 기능이다. CSV 보고서와 엑셀 양식은 1차 필수 파일이 아니다.

## 5. 기능별 입력·처리·결과·예외

### F01. 제공 자료로 시작하기

- 확정 목적: 메뉴 8개·재료 11개와 기존 운영 기록을 활용해 사용을 시작한다. 엑셀과 JSON을 중복 실적으로 가져오지 않는다.
- 사용자 행동: 처음 프로그램을 연다.
- 처리: 저장된 작업 자료가 있으면 그것을 불러온다. 없으면 준비된 제공 자료 한 세트를 사용한다. 샘플 초기화 기능을 새로 추가하지 않는다.
- 화면 결과: 가상 샘플 표시, 원자료 마감일·기록 범위, 기본 기록과 결과를 확인한다.
- 저장·파일 결과: 시작 자료를 이후 입력 기록과 함께 보존한다. 별도의 다운로드 파일은 없다.
- 예외: 필수 메뉴·재료·레시피가 빠지거나 연결되는 식별번호가 없으면 관련 결과를 ‘자료 확인 필요’로 알린다. 이미 저장된 기록이 손상되었다고 샘플로 자동 덮어쓰지 않고 복원 안내를 제공한다.

### F02. 일·월 조회와 화면 이동

- 사용자 행동: 상단 기능 이동, 일간·월간 선택, 날짜 또는 기간 선택. 시안의 채널·메뉴 필터·초기화·페이지 버튼을 사용하는 경우도 포함한다.
- 입력: 조회 기간. 판매 조회는 전체/매장/포장 채널과 전체/특정 메뉴, 메뉴 수익성은 전체/매장/포장 채널을 선택한다.
- 처리: 공통 조회 원칙에 따라 해당 기록을 선택하고 결과를 재집계한다. 페이지 이동은 목록 표시만 바꾼다. 초기화는 조회 조건만 초기 상태로 돌린다.
- 화면 결과: 현재 조건, 해당 목록, 총 기록 수·판매수량·금액, 실제 기록 범위·마감 상태. 초기화 버튼은 운영 기록을 지우지 않는다.
- 저장·파일 결과: 운영 기록 변경 없음, 파일 생성 없음. 조회 조건은 재접속 시 초기 조건으로 돌아간다. 기능 이동 시 같은 일·월을 유지하고, 페이지별 필터는 해당 화면에만 적용한다. 목록은 한 페이지 20개, 최신 날짜순으로 보여준다. 같은 날짜의 순서는 식별번호로 고정한다.
- 예외: 시작일이 종료일보다 늦거나 날짜가 잘못되면 조회하지 않고 날짜를 고치도록 알린다. 일부만 기록된 월은 그 부분만 집계하고 ‘부분 기간’임을 알린다. 빈 결과는 이전 조건의 수치를 그대로 보여주지 않는다.

### F03. 판매 목록과 신규 입력

- 사용자 행동: ‘신규 판매 기록 등록’을 누르고 값을 입력한 후 ‘기록 등록 완료’를 누른다. 취소 또는 닫기로 빠져나올 수 있다.
- 입력: 판매 날짜, 기존 메뉴, 매장/포장 채널, 판매수량, 판매단가, 총 할인액, 실제 결제수수료. 개당 식재료·포장 원가는 읽기 전용 조회값으로 보여준다. 단가는 메뉴 기준가를 참고값으로 채우되 사용자가 실제 판매단가를 확인·수정한다. 원가와 함께 적용 가격의 날짜를 표시한다.
- 입력 기준: 수량은 1 이상의 정수, 단가·수수료·할인액은 0 이상의 정수 원 금액으로 받는다. 단가 0은 무상 판매일 수 있으므로 자동 삭제하지 않는다. 할인액은 해당 집계 한 줄의 총액이며 개당 할인액이 아니다.
- 처리: 날짜에 적용되는 가격이력과 기존 레시피·채널로 개당 원가를 확인한다. 순매출을 산출하고 수량·금액·당시 원가·레시피 버전을 한 판매 기록으로 남긴다. 실제 0과 미입력은 구분한다.
- 화면 결과: 목록에 새 기록을 표시하고 F06·F09·F10에 반영한다. 현재 필터에 맞지 않는 기록을 저장했다면 숨겨졌다는 이유를 알린다.
- 저장·파일 결과: 판매 기록 한 건과 당시 기준을 보존한다. 백업 전까지 외부 파일은 만들지 않는다.
- 예외: 필수값 누락·소수 판매수량·음수·할인이 판매 총액보다 큼·없는 메뉴·없는 레시피·가격 미확인·수수료 미입력은 해당 항목을 알린다. 해당 오류를 수정한 후에 등록하며, 미확인 원가를 0으로 저장하지 않는다.
- 추가 기준: 같은 날짜·메뉴·채널 기록이 있으면 새 기록을 막고 기존 수정으로 안내한다. 미래 날짜는 실제 기록 대상이 아니므로 차단한다. 휴무일 판매는 확인 후 잠정 기록으로 허용한다. 미마감 판매는 바로 집계하되 잠정으로 표시한다. 자료의 가격은 적용 날짜를 알리고, 확인되지 않은 변경 가격을 임의 추정하지 않는다.

### F04. 판매 수정

- 사용자 행동: 행의 ‘수정’을 누르고 기존 값이 채워진 입력창에서 고친 후 저장한다.
- 처리: 대상 기록을 같은 식별번호로 갱신한다. 새 기록을 추가하거나 다른 판매를 현재 가격으로 바꾸지 않는다. 순매출·직접수익·재료 사용·기간 연결 결과를 갱신한다.
- 원가 기준: 수량·단가·할인·수수료만 고치면 기존 개당 원가를 유지한다. 날짜·메뉴·채널 변경은 원가와 레시피를 다시 확인하고 기존·새 개당 원가를 알려 확인 후 저장한다. 확인 가능한 원가가 없으면 변경을 저장하지 않는다(Q04).
- 화면 결과: 바뀐 행, 합계, 메뉴 수익성, 변경 전후 기간의 손익과 재고를 갱신한다.
- 저장·파일 결과: 해당 판매 기록을 대체하고, 관계없는 판매의 당시 원가를 유지한다. 별도 다운로드 파일은 없다.
- 예외: F03 검증을 동일 적용한다. 기록이 없어졌거나 날짜·메뉴·채널 중복이 생기면 갱신하지 않고 확인하도록 알린다. 실측 이전 판매 수정은 실측 수량을 바꾸지 않고 차이 해석을 갱신한다. 저장 실패 시 기존 자료를 유지한다.

### F05. 판매 삭제

- 사용자 행동: 행의 ‘삭제’를 누른다. 날짜·메뉴·수량을 확인하고 삭제를 확정하거나 취소한다.
- 처리: 확정한 대상만 제거하고 그 판매에 연결된 매출·비용·재료 사용을 결과에서 제외한다.
- 화면 결과: 목록·기록 수·합계·수익성·손익·재료 잔량 갱신. 마지막 행을 지운 페이지는 유효한 페이지로 이동한다.
- 저장·파일 결과: 작업 자료에서 대상 기록 삭제. 기존 백업 파일은 변경하지 않는다.
- 예외: 취소 시 변경 없음. 저장 실패 시 행을 유지하고 오류를 알린다. 실측 전 판매를 지워도 실제로 센 수량은 유지한다. 일괄 삭제는 1차 범위 밖이다.

### F06. 메뉴 수익성

- 사용자 행동: ‘메뉴별 수익성’으로 이동하고 일/월을 선택한다. 채널 필터를 선택하면 해당 채널만 비교한다.
- 처리: 판매수량·순매출·식재료원가·포장원가·수수료·직접수익을 메뉴별로 모으고, 원 금액과 순매출 대비 비율을 산출한다. 임차료·인건비를 메뉴별로 나누지 않는다.
- 화면 결과: 메뉴명·분류·판매수량·각 비용·직접수익·마진율의 상세 표와 전체 합계. 비용 구성 시각화는 같은 표의 값을 사용한다. 시안의 ‘공헌이익’은 ‘메뉴 직접수익(운영비 반영 전)’처럼 설명한다.
- 저장·파일 결과: 조회만으로 운영 기록 변경 없음. CSV 내보내기는 미승인 기능이므로 파일을 만들지 않는다.
- 예외: 판매 없음과 기록 미확인을 구분한다. 순매출 0이면 비율은 ‘계산 불가’로 표시하고 손실 원 금액은 표시한다. 음수 수익은 숨기지 않는다. 일부 원가 누락 시 전체 수익을 확정 금액처럼 표시하지 않고 해당 메뉴와 전체 집계가 불완전함을 알린다.
- 계산 기준: 마진율·식재료/포장 분류·반올림은 6장을 따른다. 채널별 단가 비교·순위 카드·전월 비교·등급은 Q01 결정에 따라 1차에서 제외한다.

### F07. 비용 목록과 신규 입력

- 확정 기능: 날짜별 비용을 직접 등록하고 목록에서 확인한다. 시안에는 빠져 있으나 새 기능이 아니라 PRD 필수 기능이다.
- 사용자 행동: 비용 관리 영역에서 날짜, 비용항목, 금액을 입력하고 저장한다. 화면 배치는 별도 설계에서 정한다.
- 입력: 날짜, 운영비 8개 항목 중 하나, 금액. 설명을 남기는 추가 칸은 이번에 필수로 확정하지 않는다.
- 처리: 날짜별 비용 한 건을 남기고 해당 일·월의 항목 합계와 손익을 갱신한다. 월비용계획을 추가 비용으로 반영하지 않는다.
- 화면 결과: 비용 목록·항목별 합계·총 운영비와 갱신된 손익.
- 저장·파일 결과: 비용 식별번호·날짜·항목·금액 저장, 별도 파일 없음.
- 예외: 날짜·항목·금액 누락, 잘못된 날짜, 음수 금액, 기존 항목 외 값은 수정하도록 알린다. 같은 날 같은 항목의 여러 비용은 실제 별도 비용일 수 있어 이름만 같다는 이유로 삭제하지 않는다. 동일 저장 요청의 중복만 방지한다.
- 추가 기준: 비용은 0 이상의 정수 원 금액이다. 실제 0원 비용은 허용하며 빈칸과 구분한다. 날짜·항목·금액이 모두 같은 기존 비용이 있으면 중복 가능성을 알리고 실제 별도 비용인지 확인 후 허용한다. 월비용계획은 원자료로 보존하며 운영비 집계에는 쓰지 않음을 표시한다.

### F08. 비용 수정·삭제

- 사용자 행동: 비용 행에서 수정하거나 삭제한다. 삭제는 날짜·항목·금액 확인 후 확정 또는 취소한다.
- 처리: 수정은 대상 기록을 바꾸고 변경 전후 날짜·월의 비용과 손익을 다시 산출한다. 삭제는 대상만 제외한다. 월비용계획을 자동 변경하지 않는다.
- 화면 결과: 비용 목록·항목 합계·기간 손익 갱신. 판매수량·메뉴 직접수익·재료 잔량은 비용 기록 변경만으로 바뀌지 않는다.
- 저장·파일 결과: 작업 자료의 대상 비용 갱신·삭제, 기존 백업 파일 변경 없음.
- 예외: F07 검증 동일 적용. 대상 없음·저장 실패는 변경하지 않고 안내. 삭제 취소는 변경 없음. 1차는 비용 환급용 음수 기록을 지원하지 않는다. 오입력 정정은 기존 비용 수정·삭제를 사용한다. 환급·반품 전용 처리는 추가하지 않는다.

### F09. 매장 기간 실적과 손익

- 사용자 행동: ‘매장 손익 현황’을 선택하고 일/월을 지정한다.
- 처리: 전체 메뉴·채널의 매출·판매수량·직접 비용을 모으고 운영비 8개 항목을 반영한다. F06 메뉴 직접수익 합계와 연결되어야 한다.
- 화면 결과: 선택 기간·실제 기록 범위, 판매수량, 순매출, 식재료·포장·수수료, 메뉴 직접수익 합계, 운영비 항목별 금액·합계, 매장 손익. 손익 화면에 비용 목록과 신규 입력·수정·삭제를 배치해 같은 화면에서 이어가도록 한다. 정확한 위치와 크기는 후속 화면 설계에서 정한다.
- 저장·파일 결과: 조회만으로 변경 없음, 보고서 파일 출력은 추가하지 않는다.
- 예외: 운영비나 판매가 일부 미입력이면 확인된 결과를 완전한 손익으로 설명하지 않는다. 손익 음수는 손실로 표시한다. 일부 월·연도 기록을 전체 기간 실적으로 확대하지 않는다. 세금·폐기 손실금액 등 범위 밖 비용을 포함한 최종 이익이라고 표시하지 않는다.
- 확정 제외: 미래 예상 손익, 재료 입고 구매대금의 별도 중복 비용, 폐기 손실금액 별도 반영.

### F10. 재료 잔량 조회

- 사용자 행동: ‘재고 잔량 및 실사’를 선택한다. 검색칸에서 재료 이름·번호로 찾는다.
- 처리: 재료별 초기재고·입고·폐기·판매 레시피 사용·실측 기준으로 조회 종료일 잔량을 산출한다. 원가 가격이 없더라도 레시피 수량이 유효하면 재료 사용량은 별도로 판단할 수 있다.
- 화면 결과: 자료의 재료번호·이름·공급사·단위·현재 장부 잔량·최근 실측과 실측일·실측 당시 차이·최종변동일. 실측이 없으면 ‘실측 기록 없음’으로 표시한다.
- 검색: 부분 이름·식별번호로 목록을 좁힌다. 검색 결과 0건은 재고가 0이라는 뜻이 아니다. 안전재고 상태 필터는 Q01 결정에 따라 1차에서 제외한다.
- 저장·파일 결과: 조회·검색은 변경 없음, 별도 파일 없음.
- 예외: 재고 음수는 0으로 덮지 않고 기록 확인 필요로 알린다. 레시피·초기재고·단위가 불명확하면 해당 재료 잔량이 확정되지 않았음을 알린다. 단위 다른 재료를 합계로 더하지 않는다.
- 처리 기준: 날짜별 판매·입고·폐기 후 하루 종료 실측(Q05). 음수 잔량은 경고하며 판매 기록은 허용하고, 재고보다 큰 폐기는 추가 확인 후 허용한다(Q06).

### F11. 입고·폐기 기록

- 사용자 행동: 상단 ‘입고/폐기 기록 등록’ 또는 재료 행 ‘입고/폐기’를 누른다. 행에서 시작하면 해당 재료를 미리 선택한다.
- 입력: 입고/폐기 구분, 재료, 수량, 날짜, 상세 사유. 수량의 단위는 재료 기준단위를 함께 보여준다. 원자료의 공급사·입고단가를 필수 입력으로 추가하지 않는다.
- 처리: 수량은 양의 크기로 입력하고, 입고는 증가·폐기는 감소로 기록한다. 기존 자료의 음수 폐기 기록을 추가 음수 처리해 증가로 바꾸지 않는다.
- 화면 결과: 저장 후 해당 재료 잔량·변동일 갱신. 성공한 구분·재료·수량·날짜를 알린다. 취소·닫기는 기록하지 않는다.
- 저장·파일 결과: 재고기록의 구분·재료·날짜·증감수량·단위·사유 저장, 별도 파일 없음. 폐기는 1차에서 손익 손실금액을 자동 생성하지 않는다.
- 예외: 재료·날짜·수량 누락, 0·음수 입력, 개 단위 소수, g/ml의 잘못된 형식은 수정 요청. 수량이 현재 잔량보다 큰 폐기는 잔량 부족을 알리고 Q06 결정에 따른다. 실측 이전 날짜의 입력은 실측 수량 자체를 바꾸지 않는다. 중복 저장·저장 실패는 F13 원칙 적용.
- 입력 기준: g/ml는 소수 셋째 자리까지, 개는 정수로 받는다. 폐기 사유는 필수, 입고 사유는 선택이다. 입력 단위를 구매 묶음으로 바꾸는 기능은 추가하지 않는다.

### F12. 실제로 센 재고와 차이 반영

- 사용자 행동: ‘정기 실사(재고 센 수량) 등록’ 또는 재료 행 ‘실사조정’을 누른다.
- 입력: 기존 재료, 실제 센 수량, 실측 기준 날짜, 차이 사유. 시안의 고정 읽기 전용 날짜를 그대로 저장하지 않는다.
- 처리: 실측 시점 장부 수량과 실제 센 수량의 차이를 구하고 실사조정으로 한 번 반영한다. 이후 잔량은 실측을 기준으로 이어간다. 실측 0은 유효하다.
- 화면 결과: 조정 전 장부·실측·차이·조정 후 잔량·사유·반영 결과. 이력 표의 ‘반영 완료’는 저장과 잔량 갱신 성공 후 표시한다.
- 저장·파일 결과: 재고기록에 실측 수량과 조정 정보를 남긴다. 조회용 차이는 관련 기록과 함께 보존한다. 추가 파일은 없다.
- 예외: 미입력·음수·잘못된 단위·없는 재료는 저장하지 않는다. 같은 재료·날짜에 실측이 이미 있으면 추가 실측을 막고 기존 기록을 안내한다(Q05). 1차에서는 실측 기록 수정·삭제를 새로 추가하지 않는다. 실측 이전 폐기를 뒤늦게 기록하면 실제 센 수량을 유지하고 당시 장부와 차이만 다시 산출한다. 실측 이후 날짜로 잘못 입력하면 잔량이 다시 줄어들 수 있음을 알린다. 실측 차이가 생겼으면 차이 사유를 필수로 받는다. 같은 수량이면 사유는 선택이다.
- 확정 원칙: 실측 이전 판매를 수정해도 실제 센 수량은 바꾸지 않는다. 그때의 장부와 조정 차이는 C05에 따라 다시 산출한다. 처음 남긴 실측 사실과 원래 조정 기록을 지우지 않고 현재 계산 기준 차이를 별도로 보여준다.

### F13. 지속 저장

- 사용자 행동: 등록·수정·삭제 완료 후 프로그램을 닫았다 다시 연다.
- 처리: 모든 정상 변경을 같은 기기의 작업 자료에 보존하고 다시 읽는다. 저장과 결과 갱신 중 일부만 성공한 상태를 완료로 처리하지 않는다.
- 화면 결과: 직전 성공한 기록과 그 결과가 유지된다. 저장 성공·실패를 알 수 있어야 한다.
- 저장·파일 결과: 기준 자료, 운영 기록, 당시 가격·원가·레시피 정보, 합의된 처리 원칙을 복원 가능한 범위로 보존한다. 사용자가 다운로드한 백업과는 구분한다.
- 예외: 저장 공간 부족·접근 불가·자료 손상은 실패 사유를 알리고 이전 성공 자료를 유지한다. 입력을 잃지 않고 재시도할 수 있게 한다. 자료가 사라졌을 때 새 샘플로 정상 운영 중인 것처럼 표시하지 않는다.
- 후속 설계: 저장 기술과 실행 환경은 기술 설계에서 정한다. 로그인·기기 공유·자동 백업을 추가하지 않는다.

### F14. 전체 백업 내려받기

- 사용자 행동: 공통 ‘데이터 백업/복원’의 백업 또는 _1 ‘수동 백업 파일 다운로드’를 선택한다. 두 진입점은 같은 전체 백업을 만든다.
- 처리: 마지막 저장 성공 시점의 전체 자료를 파일로 만든다. 현재 필터·페이지·선택한 몇 개 행으로 백업 범위를 줄이지 않는다.
- 화면 결과: 백업 대상 매장·자료 구분·시점·기록 수, 파일 생성·다운로드 결과를 알린다. 미저장 입력은 포함되지 않음을 알린다.
- 파일: 복원용 JSON 파일 한 종류. 파일명 예시 `prep-cafe-backup_20261012_143000.json`. 작성 시각은 실제 백업 시각이며 고정하지 않는다.
- 파일 내용: 파일 형식 버전, 매장·가상 샘플 여부, 백업 시각·기록 범위, 메뉴·재료·공급사·레시피·가격이력·달력·초기재고·판매·비용·재고기록·월비용계획·운영 기준. 원가 보존 정보도 포함한다. 정확한 항목 구조는 파일 설계에서 정한다.
- 예외: 파일 생성 실패·다운로드 취소·미저장 변경은 정상 백업 완료와 구분한다. 작업 자료를 변경하지 않는다. 다운로드 시작만 확인 가능하면 파일이 사용자의 디스크에 저장됐다고 확언하지 않는다.
- 확정 기준: JSON 전체 백업과 위 포함항목을 사용한다(Q07). 메뉴 수익성 CSV는 백업을 대신하지 않는다.

### F15. 전체 백업 복원

- 사용자 행동: ‘복원’을 선택해 백업 파일을 지정하고 확인된 매장·시점·자료 수를 읽은 뒤 복원을 확정하거나 취소한다.
- 처리: 파일을 먼저 검사한다. 복원은 기존 자료에 덧붙이는 가져오기가 아니라 전체 자료를 백업 시점으로 되돌리는 것이다. 복원 전 현재 자료의 보호용 JSON 백업 파일을 생성·다운로드 요청한 뒤, 사용자가 백업 확보를 확인하면 복원을 계속한다. 보호용 파일 생성 실패 또는 확인 취소 시 복원하지 않는다. 검사한 자료로 한 번에 대체한다.
- 화면 결과: 복원 전후 시점과 영향, 성공·실패, 복원 후 목록·손익·수익성·재고 갱신. 현재 조회 조건이 복원 자료와 맞지 않으면 자료 범위로 돌아가도록 안내한다.
- 저장·파일 결과: 작업 자료 전체를 복원 자료로 대체. 원래 선택한 백업 파일 자체는 변경하지 않는다. 복원 직전 현재 자료의 보호 파일을 생성한다(Q07). 다운로드 API가 실제 디스크 저장 여부를 알려주지 못하면 사용자 확인을 받는다.
- 예외: 취소·확장자만 맞는 잘못된 파일·손상·알 수 없는 형식 버전·필수 항목 누락·중복 식별번호·연결 안 되는 메뉴/재료·잘못된 단위·다른 매장 자료는 기존 자료를 변경하지 않고 이유를 알린다. 검사 통과 후 저장 실패도 원래 자료를 유지해야 한다.
- 주의: 백업 속 미마감 상태와 당시 원가를 함께 복원한다. 최신 가격으로 과거 수익성을 다시 바꾸지 않는다. 여러 백업 합치기·범용 엑셀 가져오기는 2차다.

## 6. 확정된 계산 방법

아래는 사용자의 추천안 일괄 채택으로 확정한 계산 기준이다. 실제 가격·수수료 입력값을 자료에 없는 숫자로 채우는 승인은 아니다. 시안의 예시 수치·목표율·정상 판정 기준을 그대로 사용하지 않는다. 결제수수료율을 임의로 3%·4%로 정하지 않는다.

### C01. 판매 한 줄의 매출

- 판매 총액 = 판매수량 × 판매단가.
- 순매출 = 판매 총액 − 총 할인액.
- 총 할인액은 입력할 때 양수로 받는다. 원자료도 할인 크기의 양수로 해석하며, 목록의 음수 표시는 차감을 설명하기 위한 표현이다.
- 무상 판매는 순매출이 0이어도 레시피 사용량과 실제 발생 비용이 존재할 수 있다. 무료 판매 전용 기능을 새로 추가하지 않는다.

예: 4,000원 메뉴 10개, 총 할인 2,000원이면 순매출은 38,000원이다. 수수료는 입력한 실제 금액이며 순매출에서 자동 추정하지 않는다. 이 예는 계산 설명용이다.

### C02. 새 판매의 개당 재료 원가

1. 판매 날짜·메뉴의 레시피 버전과 판매채널에 맞는 재료를 찾는다. `channel_only`가 비어 있으면 모든 채널, 포장이면 포장에만 사용한다.
2. 각 재료에서 판매일 이전 또는 당일의 적용시작일 중 가장 최근 가격 기록을 찾는다. 같은 적용일에 상충하는 가격이 있으면 임의로 하나를 고르지 않는다.
3. 기준단위 가격 = 구매 묶음 가격 ÷ 그 가격기록의 구매용량.
4. 해당 재료의 메뉴 1개당 원가 = 레시피 사용량 × 기준단위 가격.
5. 식재료 원가와 포장 원가를 각각 합산해 판매 당시 개당 원가로 남긴다.

확정 분류: 현재 자료의 I01~I09는 식재료, I10~I11은 포장 재료로 본다. ‘포장 채널에만 사용’이라는 조건 자체를 모든 미래 재료의 원가 분류 규칙으로 일반화하지 않는다. 현재 제공 자료의 원가 분류로 채택한다.

예: 원두 1,000g 묶음 가격이 23,000원이고 사용량이 20g이면 원두 원가는 460원이다. 판매 10개의 원두 사용량은 200g이다. 포장 판매에는 해당 포장세트 원가·수량이 추가된다.

필요한 가격 미확인·구매용량 0·단위 불일치는 계산하지 않고 확인 필요로 알린다. 샘플 마지막 가격이 현재 실제 가격이라고 보증하지 않는다. 기존 판매는 저장된 당시 개당 원가를 사용한다.

### C03. 메뉴별 직접수익과 비율

- 판매 식재료 비용 = 판매수량 × 저장된 개당 식재료 원가.
- 판매 포장 비용 = 판매수량 × 저장된 개당 포장 원가.
- 메뉴 직접수익 = 해당 메뉴 순매출 합계 − 식재료 비용 합계 − 포장 비용 합계 − 실제 수수료 합계.
- 메뉴 마진율 = 메뉴 직접수익 ÷ 메뉴 순매출 합계 × 100.
- 전체 마진율 = 전체 직접수익 ÷ 전체 순매출 × 100. 메뉴별 마진율을 단순 평균하지 않는다.
- 비용 구성비 = 해당 비용 ÷ 같은 범위 순매출 × 100.

순매출 0의 비율은 계산 불가다. 비용이 매출보다 커서 수익이 음수가 되어도 0으로 바꾸지 않는다. 원가가 누락된 메뉴를 빼고 전체 수익이 완전한 값인 것처럼 표시하지 않는다.

### C04. 기간 실적과 매장 손익

- 판매수량·순매출·직접 비용은 선택 범위에 포함되는 기록을 합산한다.
- 운영비 합계 = 같은 기간 날짜별 비용기록의 8개 항목 금액 합계.
- 매장 손익 = 메뉴 직접수익 전체 합계 − 운영비 합계.
- 월비용계획은 운영비 합계에 다시 더하지 않는다. 재료 입고 구매대금·폐기 손실금액·자료 없는 세금은 1차의 별도 비용으로 넣지 않는다.
- 영업달력의 휴무·미마감과 기록 없는 날을 구분한다. 아직 마감 안 된 날을 판매 0으로 채워 미래 손익을 만들지 않는다.

저장된 미마감 판매도 포함하고, 해당 결과를 잠정으로 표시한다(Q02). 월세 같은 비용은 원자료의 날짜별 비용기록을 그대로 사용한다. 새 월비용 자동 배분 계산은 2차다.

### C05. 재료 잔량·실측 차이

실측이 없는 재료:

`종료일 잔량 = 초기재고 + 입고 증감 합계 + 폐기 증감 합계 − 판매 레시피 사용량`

폐기 증감은 원자료에서 음수이므로 한 번 더 빼지 않는다. 레시피 사용량은 해당 재료의 메뉴당 사용량 × 판매수량을 모은 값이며 채널·버전을 따른다.

실측 시점:

`실측 차이 = 실제 센 수량 − 실측 직전 장부 잔량`

실측 이후:

`종료일 잔량 = 가장 최근 실측 수량 + 그 이후 입고·폐기 증감 − 그 이후 판매 사용량`

이 방식에서는 이전 초기재고·조정량을 다시 더하지 않는다. 원자료의 조정량과 실측 수량을 동시에 적용해 두 번 바꾸지 않는다. 실측 수량이 없는 실사조정 기록은 임의 입고로 취급하지 않는다. 관련 재료를 자료 확인 필요로 표시하며 전체 복원 검사에서는 유효한 실측 정보가 없는 해당 기록을 거부한다.

예: 장부 1,000g, 실측 900g이면 당시 차이는 -100g이다. 이후 500g 입고하고 200g을 사용하면 1,200g이다. 실측 이전 판매 오류가 수정돼도 실측 900g은 유지하고 당시 차이를 재검토한다.

같은 날 순서는 판매·입고·폐기 후 하루 종료 실측으로 정한다(Q05). 이는 날짜뿐인 원자료를 처리하기 위한 제품 기준이며 실제 거래 시각을 발견한 사실이 아니다. 입고·판매·폐기의 당일 중간 순서는 새로 추정하지 않고 하루 종료 잔량을 계산한다. 예전 실측과 오늘 잔량의 차이를 오늘의 실사 오차로 계산하지 않는다.

### C06. 정밀도와 표시

내부 계산에서 개당 원가 소수를 유지한다. 표시할 최종 원 금액은 원 단위, 비율은 소수 첫째 자리로 반올림한다. 중간 표시값을 다시 계산에 사용하지 않는다. 0.5는 0에서 먼 방향으로 반올림한다. 입력 금액은 정수 원이며 g/ml는 소수 셋째 자리까지, 개는 정수다. 합계는 반올림 전 값으로 계산한 뒤 표시한다. 개별 표시 금액 합과 반올림 때문에 차이가 나면 반올림 차이를 설명한다. 개당 원가 표시는 소수 둘째 자리까지, g/ml 표시는 소수 셋째 자리까지이며 끝의 불필요한 0은 생략한다. 순위·차이율·안전재고·폐기 손실·목표달성 계산은 현재 범위에 추가하지 않는다.

### 8.1 마감과 기록 범위

- 원자료의 마감 정보는 보존한다. 해당 날짜에 판매·비용·재고를 새로 기록하거나 수정·삭제하면 작업 자료의 그 날짜는 변경 후 확인 전 상태로 구분한다. 원자료가 당시 마감이었다는 사실을 지우지 않는다.
- 새 날짜와 원자료 미마감 날짜의 입력은 잠정이다. 그 기록을 메뉴 수익성·매장 손익·재료 잔량에 즉시 반영하되 확정 실적으로 표시하지 않는다. 부분 비용·부분 판매가 아직 빠져 있을 수 있음을 알린다.
- 최초 제공 자료의 마감 완료 기록은 마감 완료 기준으로 조회한다. 미마감·변경 날짜가 섞인 기간은 전체 결과에 잠정 표시를 붙이고 그 날짜를 알린다. 손익의 전체 채널 범위와 메뉴 수익성의 필터 범위는 함께 표시한다.
- 새로운 수동 마감 확정·해제 버튼은 1차에 추가하지 않는다. 새 입력을 확정 실적으로 전환하는 별도 업무 기능은 이후 범위 변경 시 결정한다. 1차는 기록을 입력하고 잠정 결과를 검토하는 데 집중한다.
- 기록 없는 미마감 날짜는 0으로 채우지 않는다. 영업 마감이 확인된 제공 날짜에서 해당 메뉴 판매가 없으면 그 메뉴의 수량·금액을 0으로 표시할 수 있다. 미마감 날짜에 해당 메뉴 기록이 없으면 ‘기록 없음’이지 확정 0은 아니다.
- 달력 범위 밖 날짜에도 오늘 또는 과거의 실제 판매·비용·재고를 입력할 수 있다. 해당 날짜의 영업 여부는 미확인, 마감은 잠정으로 남긴다. 영업일 설정 기능을 새로 추가하지 않는다.

### 8.2 중복과 입력 예외

- 판매는 날짜·메뉴·채널 중복을 막는다. 자동 추가 합산과 단가 평균 처리는 하지 않는다. 다른 가격의 판매가 섞인 집계를 입력하려면 전체 수량·금액에 맞는 집계가 먼저 필요하며, 여러 단가의 주문별 기록 기능은 1차에 추가하지 않는다. 정수 단가 한 줄로 실제 금액을 표현할 수 없으면 거짓 단가로 저장하지 않고 1차 지원 범위 밖임을 알린다.
- 원자료·복원 자료에서 같은 날짜·메뉴·채널 중복이 발견되면 자동 합치지 않는다. 최초 자료는 문제를 알리고 해당 집계를 확인 필요로 표시한다. 복원 검사는 중복된 판매 집계가 있는 파일을 거부한다.
- 금액은 정수 원, 판매·개 단위 수량은 정수다. 수량 0인 신규 판매는 차단하며 판매 없음은 기록을 추가하지 않는 방식으로 표현한다. 원자료의 유효한 0은 임의 변경하지 않는다.
- 미래 날짜의 신규·수정 입력은 차단한다. 날짜 기준은 한국 시간이다. 휴무일 실제 기록은 경고 후 확인하면 저장하되 휴무 달력을 자동 변경하지 않는다.
- 단가 0의 실제 무상 판매, 0원 할인·수수료·비용, 실측 0은 허용한다. 수수료가 순매출보다 큰 경우에는 확인 후 허용하고 손실을 표시한다. 음수 금액·환불·비용 환급 전용 기록은 1차에서 지원하지 않는다.
- 입고는 사유 선택, 폐기는 사유 필수다. 실측 차이가 0이 아니면 사유 필수다. 실제 사유를 시스템이 만들어 넣지 않는다.
- 같은 재료·날짜의 실측은 한 번만 등록한다. 기존 실측의 직접 수정·삭제는 2차 범위이며, 최초 입력 전에 날짜·재료·수량을 확인한 후 저장한다.
- 기록상 잔량이 부족해도 실제 판매는 허용하고 경고한다. 잔량을 0으로 보정하지 않는다. 폐기량이 그 날짜의 실측 전 기록상 잔량보다 크거나 음수 잔량을 만들면 대상·수량·예상 잔량을 알리고 추가 확인 후 등록한다.

### 8.3 원가 확인과 누락 처리

- 새 판매 원가는 판매 날짜에 적용되는 가격이력으로 산출한다. 묶음 가격과 용량은 같은 가격기록에서 가져온다. 적용시작일이 같은 상충 가격·구매용량 0·단위 불일치가 있으면 새 판매 저장을 차단한다.
- 확인 가능한 가격이력이 있으면 그 적용일과 ‘등록된 가격 기준’을 표시한다. 이후 가격 변경 기록이 없다는 사실만으로 현실에서도 변경이 없었다고 보증하지 않는다. 운영자가 실제와 다름을 확인했거나 적용 가능한 가격 자체가 없으면 저장하지 않고 가격 자료 확인을 안내한다. 가격 편집 화면을 새로 추가하지 않는다.
- 기존 판매의 저장된 당시 원가는 보존한다. 새 원가 산출 결과와 다르다고 자동 덮어쓰지 않는다. 기존 기록의 필수 원가·수수료가 누락되면 직접수익과 그에 의존하는 손익은 계산 불가로 표시하고, 확인 가능한 판매수량·순매출 등만 따로 보여준다.
- 원가가 일부 빠진 경우 누락 비용을 0으로 처리하거나 계산 가능한 메뉴만 모아 전체 이익이라고 표시하지 않는다. 어떤 메뉴·기록이 결과를 막는지 알린다.
- 초기재고·레시피·단위가 불명확한 재료의 잔량도 계산 불가로 표시한다. 원가 가격 문제만 있고 사용량 자료는 유효하면 수량 계산은 독립적으로 진행한다.
- 실측 전 기록을 수정해도 실제 센 수량은 유지한다. 실측 시점의 현재 기준 장부·차이는 다시 산출하고 원래 실측·조정 기록은 함께 보존한다. 실측 후 기간을 계산할 때 원래 조정량까지 다시 더하지 않는다.

### 8.4 백업과 복원 검사

- 백업 파일 형식은 프로그램 전용 JSON이며 원자료 JSON 자체를 복원용 백업으로 오해하지 않는다. 백업 형식 버전과 데이터 출처 버전은 구분한다. 정확한 필드 이름은 구현 설계에서 정한다.
- 필수 범위는 매장·자료 구분·시점·형식 버전, 기준 자료, 판매·비용·재고, 원가·레시피 보존 정보, 달력과 변경 후 잠정 상태, 업무 기준이다. 검색 조건·표 표시 페이지는 운영 기록이 아니므로 백업 필수 범위에서 제외한다.
- 복원 검사는 형식 버전·필수 정보·중복 식별번호·판매 집계 중복·단위·레시피·기준 자료 연결·마감 상태를 확인한다. 1차는 같은 매장과 현재 프로그램이 지원하는 백업 형식만 허용한다. 샘플/실제 구분이 다른 파일도 거부한다.
- 계산값으로 가능한 음수 재고·손익이나 실제 0은 그 값이라는 이유만으로 파일을 거부하지 않는다. 입력 허용 기준 위반·손상·필수값 누락은 거부한다. 기존 무효 자료를 정상 파일로 간주하지 않는다.
- 파일 검사 통과 후 기존 자료의 보호 백업을 먼저 확보하고 복원 범위를 확인한다. 검사·보호 파일 생성·기존 자료 저장 중 하나라도 실패하면 복원하지 않고 기존 자료를 유지한다. 전체 자료 교체 후 결과를 다시 산출하되 과거 원가를 현재 가격으로 바꾸지 않는다.

### 8.5 후속 설계와 2차에 남기는 사항

화면의 정확한 배치·크기, 저장 기술, 실행 환경, 파일 필드 구조·지원 버전의 실제 번호는 후속 구현 설계에서 정한다. 이는 기능이나 계산 기준의 미정이 아니다. 실제 구매가격·수수료와 자료 누락은 운영 확인 대상이다. 엑셀 가져오기·발주량·전망·공동 사용 등 2차 정책은 10장처럼 보류하며 이번 일괄 채택으로 자동 확정하지 않는다.

4시간 구현 예산은 PRD의 기획 25분·화면 설계 20분·개발 135분·검사 40분·배포 20분을 유지한다. 이 문서가 완성되었다고 개발이나 검사가 완료된 것은 아니다. 후속 구현에서는 제외한 시안 요소를 되살리지 않고, F01~F15의 연결과 저장·복구 검사에 시간을 우선 배정한다.

## 9. 검사할 완료 조건

다음은 승인된 상세 기준을 실제 기능에서 확인하기 위한 검사 항목이다. 지금 구현·검사를 완료했다는 뜻은 아니다.

1. 샘플이 중복 적재되지 않고 메뉴 8개·재료 11개·연결 기록을 유지한다.
2. 판매 신규·수정·삭제가 메뉴 수익성·손익·재료 잔량에 연결된다. 날짜 변경은 변경 전후 기간 모두에서 확인한다.
3. 포장 판매만 포장 전용 재료를 사용하고, 판매 가격 변경이 과거 원가를 임의 변경하지 않는다.
4. 비용 신규·수정·삭제가 운영비·매장 손익에 반영되고 메뉴 직접수익이나 재고는 바뀌지 않는다.
5. 일·월·마감·부분 기간·기록 없음·실제 0을 구분한다. 표와 요약은 같은 범위·계산 결과를 사용한다.
6. 입고·폐기의 부호, 실측 0, 실측 전후 판매 변경, 같은 날 순서, 음수 잔량을 승인 기준대로 처리한다.
7. 미확인 가격·수수료·레시피가 수익 또는 재고 0으로 숨겨지지 않는다. 순매출 0의 비율도 점검한다.
8. 재접속 후 직전 저장 성공 기록과 결과를 확인한다. 실패와 취소 시 이전 자료를 유지한다.
9. 전체 백업 후 판매·비용·재고를 바꾸고 복원했을 때 기록·당시 원가·마감 상태·핵심 결과가 백업 시점과 일치한다.
10. 잘못된 백업·호환 안 되는 버전·저장 실패는 기존 자료를 변경하지 않는다.
11. 시안의 가짜 완료 표시·고정 수치·미승인 버튼이 실제 운영 기능처럼 남아 있지 않다.
